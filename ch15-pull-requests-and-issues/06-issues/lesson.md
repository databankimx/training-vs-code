# Issues

An issue is a place to track work that is not a change yet: a bug, a question, or an idea. A pull request is usually the change that closes an issue. The two are linked, so the issue closes automatically when the pull request is merged.

On the website, open the Issues tab of your practice repository and choose New issue. Give it a title, such as `Add a second line to the README`, and a short description. Submit it. GitHub gives the issue a number, such as `#1`.

To link a pull request to the issue, write `Closes #1` in the pull request description, using your issue's number. When that pull request merges, the issue closes on its own.

The GitHub Pull Requests extension also shows issues in its own view, so you can open, read, and comment on an issue from VS Code.

> **The link is written in the description.** Writing `Closes #1` in a commit message does not link the issue. Put it in the pull request description, where GitHub reads it.
