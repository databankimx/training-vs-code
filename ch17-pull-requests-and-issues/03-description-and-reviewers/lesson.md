# Description and reviewers

The title says what the change is. The description says why, and what the reviewer should check. A good description answers three questions: what changed, why, and how to test it.

For this pull request, write something like this:

```
Adds a line to the README so the pull request has a change to review.

Check that the line is at the end of the file and that nothing else changed.
```

## Reviewers

A reviewer is the person GitHub asks to read the pull request. You can request one in the Reviewers box on the website, or in the pull request view in VS Code. The person you pick must have access to the repository.

For the practice repository, you have no second account, so you cannot request a reviewer yourself. Skip this step, and go on to the checks and comments. At work, your team's codeowner rules decide who must approve.

> **Changes after the request.** Once a reviewer is requested, a new commit on `pr-practice` appears in the pull request automatically. You do not need to open a new pull request.
