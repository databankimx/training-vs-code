# Clean-day checklist

Tick a step by changing `[ ]` to `[x]` in the editor, not in the preview. The preview shows the boxes, but it does not let you click them. Keep this file with you, and tick it as you go.

## Open

- [ ] Open the folder in VS Code, in its own window. (Chapter 3)
- [ ] Check the branch name in the status bar, and the Changes list in Source Control. (Chapters 10 and 11)
- [ ] Sync with the remote, if the folder is shared, and resolve anything that needs it. (Chapters 12 and 13)

## Branch

- [ ] Create a branch for the change, with a short name. (Chapter 11)
- [ ] Check the branch name in the status bar before you edit. (Chapter 11)

## Edit

- [ ] Make the change with the editor's tools: find and replace, multiple cursors, and IntelliSense. (Chapters 5 to 7)
- [ ] Save the file, or let auto save do it. (Chapter 20)

## Test

- [ ] Run the tests from the terminal, and read the expected and actual values. (Chapters 8 and 9)
- [ ] If a test fails, debug it from the Testing view with a breakpoint. (Chapter 9)
- [ ] Run the tests again until they pass for the right reason. (Chapter 23)

## Commit

- [ ] Review each changed line in the diff. (Chapter 10)
- [ ] Stage only what you checked, and write a clear message. (Chapter 10)
- [ ] Commit. (Chapter 10)

## Push and review

- [ ] Publish the branch, or push or sync if it already exists. (Chapters 12 and 15)
- [ ] Open a pull request with a description a reviewer can follow. (Chapter 15)
- [ ] Use Copilot's explanations only as a claim to check against the code and the tests. (Chapters 16 to 18)
- [ ] Review the pull request's checks and comments before you merge. (Chapter 15)
