# The clean-day checklist

Work through these in order each time you sit down to change code. To keep a copy you can tick off, [save the checklist file](../docs/clean-day-checklist.md). It opens in your default app, and you can change `[ ]` to `[x]` as you go. Each step names the chapter that taught it, so you can go back if a step is unclear.

## Open

- [ ] Open the folder in VS Code, in its own window. (Chapter 3)
- [ ] Check the branch name in the status bar, and the Changes list in Source Control. (Chapters 11 and 12)
- [ ] Sync with the remote, if the folder is shared, and resolve anything that needs it. (Chapters 13 and 14)

## Branch

- [ ] Create a branch for the change, with a short name. (Chapter 12)
- [ ] Check the branch name in the status bar before you edit. (Chapter 12)

## Edit

- [ ] Make the change with the editor's tools: find and replace, multiple cursors, and IntelliSense. (Chapters 5 to 7)
- [ ] Save the file, or let auto save do it. (Chapter 21)

## Test

- [ ] Run the tests from the terminal, and read the expected and actual values. (Chapters 8 and 10)
- [ ] If a test fails, debug it from the Testing view with a breakpoint. (Chapter 10)
- [ ] Run the tests again until they pass for the right reason. (Chapter 24)

## Commit

- [ ] Review each changed line in the diff. (Chapter 11)
- [ ] Stage only what you checked, and write a clear message. (Chapter 11)
- [ ] Commit. (Chapter 11)

## Push and review

- [ ] Publish the branch, or push or sync if it already exists. (Chapters 13 and 16)
- [ ] Open a pull request with a description a reviewer can follow. (Chapter 16)
- [ ] Use Copilot's explanations only as a claim to check against the code and the tests. (Chapters 17 to 19)
- [ ] Review the pull request's checks and comments before you merge. (Chapter 16)
