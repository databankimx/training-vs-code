# Open the practice repository

Your first job is to look before you touch anything. Red tests are often caused by leftover changes, and a lot of wasted afternoons begin with someone editing the wrong copy of the code. So you open the practice repository, and you check that it is clean. Think of it as walking into a room before you start moving furniture.

## Open the folder

Open the practice repository you made in your own GitHub account, in Chapter 2. Use File, then Open Folder, and choose the folder. If the window already shows a different project, open this one in a new window, so your other work stays where it is.

## Check the Git status

Open the Source Control view with {{Ctrl+Shift+G}}. The branch name shows in the status bar at the bottom of the window. It should be `main`. The Changes list should be empty. If it is not, read each change before you do anything else. A change you do not recognise is a question to answer first, not a file to commit.

## Why check first

If you start a branch with leftover changes, those changes come along for the ride, and they end up in your commit without you choosing them. A minute spent checking saves a commit you have to undo later.

> **Check before you branch.** An empty Changes list and the `main` branch in the status bar are the starting point for everything in this chapter.
