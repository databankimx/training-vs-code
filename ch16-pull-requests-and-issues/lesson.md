# 15. GitHub: Pull Requests and Issues

A pull request is a request to merge one branch into another. You push a branch, open a pull request, and the people who review it read the changes, leave comments, and approve them. Once the review is done, someone merges the branch. The pull request keeps the discussion and the decision in one place, so there is a record of why a change was accepted.

At DataBank, most of this happens on the GitHub website, and this chapter shows that route first. The GitHub Pull Requests extension does the same work inside VS Code, and the lessons show both, so you can use whichever you prefer.

Work repositories have a rule that matters here. Direct commits and merges to `main` are blocked, so every change reaches `main` through a pull request that a codeowner approves. The practice repository lets you merge your own pull request, so you can finish the whole flow alone. At work, you need a second person to approve it.

The practice repository is in your own GitHub account, and you will be both the author and the person who merges. GitHub does not let you approve your own pull request, so the review steps leave comments instead.
